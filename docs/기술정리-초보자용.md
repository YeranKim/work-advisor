# Work Advisor 기술 정리 문서 (초보자용)

> 보험사 사내 IT 업무를 "과거 사례"로 찾아 답해 주는 검색 도우미(Agent)입니다.
> 이 문서는 코딩을 처음 접하는 사람도 프로젝트 전체를 이해할 수 있게 쉬운 말로 정리했습니다.

---

## 1. 이 프로젝트가 뭐예요? (한 문장 요약)

**"사내 IT 업무 질문을 하면, 비슷한 과거 처리 사례를 찾아서 '이렇게 하면 됩니다'라고 알려주는 검색 도우미"** 입니다.

예를 들어 이렇게 씁니다.

- 질문: "계약계 DB 조회 계정 발급은 어떻게 신청하나요?"
- 도우미: 과거에 똑같은 일을 처리했던 사례를 찾아서 → 필요한 서류, 결재 순서, 처리 절차, 주의사항을 정리해 답변

즉, 사람이 매번 "이건 누구한테 신청하지? 무슨 서류가 필요하지?"를 고민하지 않도록, **과거 경험(사례)을 대신 기억하고 찾아주는 시스템**입니다.

---

## 2. 왜 만들었나요? (해결하려는 문제)

회사 IT 업무는 종류가 아주 많습니다. 계정 발급, VPN 신청, 방화벽 오픈, 프로그램 설치, 장애 처리... 각각 필요한 서류와 결재선이 다 다릅니다.

- 신입/담당자는 "이 업무는 어떻게 처리하지?"를 매번 물어봐야 합니다.
- 답을 아는 사람은 같은 질문에 계속 답해야 합니다.

이 프로젝트는 **과거에 실제로 처리했던 사례 303건을 쌓아 두고**, 새 질문이 들어오면 그중 가장 비슷한 사례를 찾아 답의 근거로 씁니다.

> 참고: 지금 들어있는 사례 303건은 시연을 위해 만든 **가상(합성) 데이터**입니다. 실제 회사 데이터로 바꾸면 그대로 실무에 쓸 수 있는 구조입니다.

---

## 3. 어떤 질문에 답할 수 있나요? (11개 업무 영역)

과거 사례는 11개 IT 업무 영역으로 나뉘어 있습니다. (괄호 안은 현재 사례 개수)

| 업무 영역 | 사례 수 | 예시 질문 |
|---|---|---|
| DB 계정·권한 | 28 | "운영 DB 조회 계정 발급" |
| 사내 계정·그룹웨어 | 28 | "퇴직자 계정 회수" |
| VPN·원격접속 | 28 | "재택 VPN 신청" |
| 프로그램 설치 | 27 | "개발 IDE 설치" |
| 서버 접근·작업 | 27 | "운영 서버 SSH 접근" |
| 방화벽·네트워크 | 27 | "방화벽 포트 오픈" |
| 배포·변경관리 | 27 | "운영 배포 변경 신청" |
| 배치·인터페이스 장애 | 27 | "야간 배치 실패" |
| 개인정보·데이터 추출 | 27 | "고객정보 추출 승인" |
| 인증서·암호화키 | 27 | "SSL 인증서 갱신" |
| IT 장애·문의 | 30 | "보안접속 에이전트 끊김" |

전체 **303건 + 담당자 연락처 정보 1건 = 총 304줄**의 데이터가 들어 있습니다.

각 사례는 아래 상태 중 하나를 가집니다.

- **완료** (155건): 정상 처리됨
- **보완 후 완료** (47건): 서류가 빠져 보완한 뒤 처리됨
- **반려** (54건): 요건 부족으로 거절됨 → "이러면 반려된다"는 교훈으로 활용
- **진행 중** (47건): 아직 처리 중

## 4. 전체 그림 (데이터가 어떻게 흘러가나)

```
[사용자 질문]
     │
     ▼
[ ask.py ]  ← 검색을 실행하는 입구(명령어)
     │
     ▼
[ search.py ]  ← 실제로 사례를 찾는 두뇌
     │  ┌──────────────────────────────┐
     │  │ ① 벡터 검색 (의미로 찾기)      │
     │  │ ② BM25 검색 (키워드로 찾기)   │
     │  │ ③ 두 점수를 합쳐 순위 결정     │
     │  └──────────────────────────────┘
     ▼
[ 가장 비슷한 사례 Top 5 ] + [ 이게 믿을 만한지 판정(weak_match) ]
     │
     ▼
[ 채팅 도우미가 사례를 근거로 답변 작성 ]
```

## 5. 핵심 기술: "하이브리드 검색"이 뭐예요?

가장 중요한 부분입니다. 사례를 찾을 때 **두 가지 방법을 동시에** 씁니다.

### 방법 A. 벡터 검색 (의미로 찾기)

- 문장의 **뜻**을 숫자 묶음(벡터)으로 바꿔서, 뜻이 비슷한 사례를 찾습니다.
- 단어가 달라도 의미가 같으면 잡아냅니다.
  - 예: "로그인 안 됨" ↔ "인증 실패" → 단어는 다르지만 같은 뜻으로 인식
- 사용하는 AI 모델: `intfloat/multilingual-e5-base` (여러 언어를 이해하는 문장 임베딩 모델)
- 빠른 검색을 위해 **FAISS**라는 벡터 검색 엔진을 씁니다.

### 방법 B. BM25 검색 (키워드로 찾기)

- 질문에 나온 **정확한 단어**가 사례에 얼마나 겹치는지로 찾습니다.
- 약어나 시스템 이름에 강합니다.
  - 예: "TLS", "SSH", "VPN" 같은 정확한 용어

### 왜 둘 다 쓰나요?

- 벡터만 쓰면: 뜻은 잘 잡지만, 정확한 약어를 놓칠 수 있음
- BM25만 쓰면: 단어가 다르면 못 찾음
- **둘을 합치면** 서로의 약점을 메워 줍니다.

### 두 점수를 어떻게 합치나요?

각 점수를 0~1 사이로 맞춘(정규화한) 뒤, 가중치를 곱해서 더합니다.

```
최종점수 = (벡터점수 × 0.6) + (BM25점수 × 0.4)
```

벡터 검색이 더 똑똑해서 비중(0.6)을 조금 더 줬습니다.

## 6. "엉뚱한 답"을 막는 안전장치 (weak_match)

검색은 항상 "가장 비슷한 것"을 돌려줍니다. 문제는, **정답이 없어도 억지로 뭔가를 돌려준다**는 점입니다.

예를 들어 "사원증 발급"은 IT 업무 사례에 없는데도, 검색은 그나마 비슷해 보이는 걸 내놓습니다. 이걸 그대로 답하면 **틀린 안내**가 됩니다.

그래서 "이 검색 결과를 믿어도 되는가?"를 판정하는 게이트가 있습니다. 이름이 `weak_match`(약한 매칭)입니다.

아래 **셋 중 하나라도** 해당하면 `weak_match = true` (믿을 수 없음)로 판정합니다.

1. 검색 결과가 아예 없음
2. 1위 사례의 **의미 유사도(벡터 점수)가 0.83 미만** → 뜻이 별로 안 비슷함
3. 1위 사례의 **키워드 매칭이 바닥(0.05 미만)** → 문장 형식만 비슷하고 실제 단어가 하나도 안 맞음

`weak_match = true`이면 → 사례로 절차를 지어내지 않고, **"맞는 사례가 없습니다"라고 밝힌 뒤 담당자 연락처를 안내**합니다.

> 2번과 3번의 차이가 핵심입니다.
> 벡터 점수는 "문장 구조가 비슷"하기만 해도 높게 나올 때가 있습니다(오탐). 그럴 때 키워드 매칭(3번)이 0에 가까우면 "사실은 관련 없는 사례"라고 걸러냅니다. 이게 하이브리드 검색을 안전장치로도 활용하는 부분입니다.

---

## 7. 답을 못 찾으면? (담당자 안내)

`weak_match`가 뜨면, 데이터에 저장된 **담당자 연락처**를 안내합니다.

- 데이터 파일 맨 끝에 담당자 정보가 특수한 한 줄(`record_type: contacts`)로 들어 있습니다.
- 어디로 가야 할지 모를 때의 기본 창구는 **IT 서비스데스크 (내선 1234)** 입니다.
- 업무 영역별 전담 담당자도 등록되어 있습니다.
  - 예: 인증·세션 정책 변경 → 인증인프라팀 (내선 3320)

이렇게 하면 "모르는 걸 아는 척"하지 않고, 정확히 사람에게 넘겨줍니다.

## 8. 파일 구조 (무엇이 어디에 있나)

```
work-advisor/
├── data/processed/
│   └── insurance_it_cases.jsonl   ← 사례 데이터 (한 줄 = 사례 1건, 총 304줄)

│   ├── metadata.jsonl              ← 색인과 사례를 연결하는 정보

│   └── search.py                   ← 핵심 두뇌: 하이브리드 검색 + 담당자 조회

│   ├── prepare_cases.py            ← 원본 데이터 다듬기

├── skill/
│   ├── SKILL.md                    ← 채팅 도우미가 따르는 사용 설명서

│
├── docs/
│   └── work-advisor-presentation.html  ← 발표용 슬라이드
│
├── requirements.txt                ← 필요한 파이썬 라이브러리 목록

```

## 9. 파일별 역할 (쉬운 설명)

| 파일 | 하는 일 | 비유 |
|---|---|---|
| `insurance_it_cases.jsonl` | 모든 과거 사례를 담은 원본 데이터 | 경험이 쌓인 **사례집** |
| `create_index.py` | 사례를 검색하기 좋게 색인으로 변환 | 책에 **찾아보기(색인)** 만들기 |

| `ask.py` | 사용자가 질문을 넣는 창구 | 사서에게 말을 거는 **접수 창구** |
| `show_case.py` | 특정 사례 하나를 자세히 보여줌 | 책 한 권을 **펼쳐 보기** |
| `SKILL.md` | 채팅 도우미의 행동 규칙 | 도우미의 **업무 매뉴얼** |

## 10. 실제로 어떻게 실행하나요?

### 준비 (최초 1회)

파이썬 가상환경을 만들고 라이브러리를 설치합니다.

```
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

### 질문하기

```
venv/bin/python scripts/ask.py "계약계 DB 조회 계정 발급은 어떻게 신청하나요?" --top-k 5 --json
```

- `--top-k 5` : 가장 비슷한 사례 5건까지 보기
- `--json` : 채팅 도우미가 읽기 좋은 형태(JSON)로 출력
- `--category "VPN·원격접속"` : 특정 영역만 검색 (선택)
- `--status "반려"` : 특정 상태만 검색 (선택)

### 특정 사례 자세히 보기

```
venv/bin/python scripts/show_case.py SYN-IT-DBA-0001
```

### 데이터를 바꿨을 때 (색인 다시 만들기)

```
venv/bin/python scripts/create_index.py
```

> 데이터를 수정하면 반드시 색인을 다시 만들어야 검색이 정확합니다.
> (사례 개수와 벡터 개수가 일치해야 합니다.)

## 11. 검색 결과에는 뭐가 들어있나요? (사례 필드 설명)

검색 결과 한 건에는 아래 정보가 들어 있습니다.

| 필드 | 뜻 |
|---|---|
| `case_id` | 사례 고유 번호 (예: SYN-IT-DBA-0001) |
| `category` | 업무 영역 |
| `status` | 완료 / 보완 후 완료 / 반려 / 진행 중 |
| `title` | 사례 제목 |
| `situation` | 어떤 상황이었는지 |
| `required_documents` | 필요한 서류 |
| `missing_document` | 빠져서 문제가 됐던 서류 (있을 때만) |
| `approval_route` | 결재 순서 (누가 → 누가) |
| `required_tools` | 필요한 도구/프로그램 |
| `pre_checks` | 처리 전 확인 사항 |
| `process_steps` | 실제 처리 절차 (단계별) |
| `cautions` | 주의사항 |
| `outcome` | 최종 결과 |
| `score` / `vector_score` / `bm25_norm` | 내부 검색 점수 (사용자에게는 보여주지 않음) |

> 마지막 점수 3개는 **내부 판단용**입니다. 사용자에게 답할 때는 이런 숫자를 노출하지 않고, "맞는 사례가 있으면 절차 안내 / 없으면 담당자 안내"라는 결과만 자연스럽게 전달합니다.

## 12. 이 프로젝트의 설계 원칙 (왜 이렇게 만들었나)

1. **지어내지 않는다** — 사례에 있는 내용만 답하고, 없으면 "없다"고 말합니다.
2. **틀리느니 넘긴다** — 확신이 없으면(weak_match) 담당자에게 안내합니다.
3. **반려 사례도 자산** — "이러면 거절된다"는 실패 경험도 주의사항으로 활용합니다.
4. **내부 수치는 숨긴다** — 점수·임계값 같은 기술 용어는 사용자에게 보이지 않습니다.
5. **영역을 한정 짓지 않는다** — "이건 IT 범위 밖"이라고 단정하지 않고, 데이터에 맞는 사례가 있는지로만 판단합니다.

## 13. 한눈에 보는 용어집

| 용어 | 쉬운 설명 |
|---|---|
| **임베딩 / 벡터** | 문장의 뜻을 숫자 묶음으로 바꾼 것. 뜻이 비슷하면 숫자도 비슷함 |
| **FAISS** | 수많은 벡터 중 비슷한 걸 빠르게 찾아주는 검색 엔진 |
| **BM25** | 단어(키워드)가 얼마나 겹치는지로 점수를 매기는 고전 검색 방식 |
| **하이브리드 검색** | 벡터(의미) + BM25(키워드)를 합친 검색 |
| **정규화(min-max)** | 서로 다른 점수를 0~1 사이로 맞춰 공정하게 비교하는 것 |
| **weak_match** | "이 검색 결과 믿어도 되나?"를 판정하는 안전장치 |
| **폴백(fallback)** | 답을 못 찾았을 때 대신 담당자에게 안내하는 것 |
| **JSONL** | 한 줄에 하나의 데이터(JSON)가 들어있는 파일 형식 |
| **venv** | 이 프로젝트 전용으로 라이브러리를 격리해 설치하는 파이썬 가상환경 |
